# News to Level

The only in-game news UI is the title screen's NEWS LEVELS section, which lists every level whose `content.news` marker is set. This skill is otherwise the product: a Muse (Spark harness) workflow run on the command line in this repo. The agent fetches real news from free feeds (Google News RSS, HN, outlet RSS; web search as backup), the user picks a story (or asks for a random one), and the agent generates the art and the level by invoking this repo's existing skills, then proves it plays.

Run it by opening Muse in this repo and saying: "run news-to-level", "make a level from today's news", or "surprise me with a news level".

## 1. Get today's news (free feeds first, web search as backup)

Pull 5–6 recent, reputable headlines (prefer the last 24 hours; favor non-graphic stories). The list must span at least three beats (e.g. space, markets, sport, science, tech, culture, weather) — stories do not all need to be about space, and at most half the list may share one beat. Before listing, check the beats of the last few shipped news levels (`content.news` headlines in `levels/*.js`) plus the already-used stories (`node scripts/news-used-stories.mjs`), and lean the list away from recently covered beats. For each, verify the link actually resolves and note headline, outlet, publication time, and URL. Never invent a headline, date, or citation.

**Primary: free feeds and APIs (no key).** Mix these to cover the beats — no single source needs to carry the whole list:
- **Google News RSS** — broadest source for any beat. Top stories: `https://news.google.com/rss?hl=en-US&gl=US&ceid=US:en`; per-topic search: `https://news.google.com/rss/search?q=<term>&hl=en-US&gl=US&ceid=US:en`. Parse `title`/`link`/`pubDate` with `python3 -c` (`xml.etree`). Titles end in ` - Outlet` (that suffix is the outlet); `link`s are Google redirect URLs, so follow them (`curl -sIL -o /dev/null -w '%{url_effective}'`) to record the real article URL.
- **Hacker News Algolia API** — best free tech-beat source, community-ranked. Front page: `https://hn.algolia.com/api/v1/search?tags=front_page`; search: `https://hn.algolia.com/api/v1/search?query=<term>&tags=story`. Each hit has `title`, `url`, `points`, `created_at`. Tech-beat only — never build the whole list from it.
- **Direct outlet RSS** — `curl` a section feed and parse `title`/`link`/`pubDate`: BBC `https://feeds.bbci.co.uk/news/rss.xml` (plus `/world`, `/science_and_environment`, `/technology`, `/business`), NPR `https://feeds.npr.org/1001/rss.xml`, CBC `https://www.cbc.ca/webfeed/rss/rss-topstories`, NASA `https://www.nasa.gov/rss/dyn/breaking_news.rss`, ESA `https://www.esa.int/rssfeed/TopNews`, ESPN `https://www.espn.com/espn/rss/news`.

Prefer established outlets (BBC, AP, Reuters, NPR, NYT, Guardian, ESPN, SpaceNews, Ars, etc.) over aggregators and wire copies. Confirm each candidate's URL resolves (`curl -sI -o /dev/null -w '%{http_code}' <url>`) before listing it.

**Fallback: web search.** If the feeds are unavailable, gather the same headline/outlet/time/URL fields with web search.

Present the list in the terminal, numbered, one line each: headline — outlet, time. Then stop and let the user pick a number.

- If the user picks one, use it.
- If the user says "random", "surprise me", or gives no pick, choose one with `shuf -i 1-N -n 1` (or `$RANDOM`) and announce which story chance picked.
- If the user pastes a headline, URL, or speaks a topic ("today's space news as a low-gravity boss fight"), treat that text as the story instead of listing.

### Unattended mode ("surprise me" / auto)

With no human to filter the list, run `node scripts/news-used-stories.mjs` first, exclude every already-used story it lists, prefer a beat the last two shipped news levels did not cover, and pick from the remainder with `shuf`. A tragedy/disaster pick must declare an abstract rescue/logistics objective up front or be skipped for the next pick — never build it as combat against victims.

Re-fetch the chosen article and extract only facts: what happened, where/when, the forces and motion involved (rising water, low gravity, heat, collapse, speed), who needs rescuing or what must be reached, and the scale. Keep facts and invented fiction visibly separate. For tragedies or disasters, design abstract rescue/logistics mechanics — never victims as enemies.

## 2. Direct it in the terminal (before touching files)

Print a mapping table with at least three rows where the story changes gameplay, not just scenery:

| Story fact       | Gameplay it becomes                                                  | Why      |
| ---------------- | -------------------------------------------------------------------- | -------- |
| (quote the fact) | gravity / hazard type+timing / objective / topology / enemy behavior | one line |

Examples: orbital rescue → gravity 150 + drone patrols + rescue cages; river flood → rising-water harbor decks + drip hazards + escape objective. Then name the level slug, biome, and boss idea if any. One short user confirmation is enough to proceed; if they said "surprise me", proceed without asking again.

Mark the signature items in the brief before anything is built: add a `Signature elements: a, b` line naming a subset of the element inventory (below), and mark the signature fact→mechanic row by suffixing its fact cell with ` (signature)`. The fidelity critic parses exactly these marks; an unmarked brief fails closed.

Then write the level's three creativity artefacts (see `skills/level-creator/SKILL.md`): the Novelty Ledger against the three nearest shipped levels, the Signature Mechanic Canvas (the story's strongest force becomes the taught verb — a crash _falls_, a flood _rises_, a rescue _carries_), and the Topology Fingerprint (the route's shape embodies the story: a plunge descends, a blackout darkens room by room). Run the **Concept critic** before art with `npm run critic:concept -- --brief docs/level-builds/<id>.md` (see `skills/game-critic/SKILL.md`) — it works before the level exists and checks the Novelty Ledger, Signature Mechanic Canvas, Topology Fingerprint, ≥3 fact→mechanic rows that are not scenery-only, element inventory ≥3, and a named themed enemy. If the concept scores as a clone or the mechanics are scenery-only, re-direct now while it is still words. News `critic:level` runs also assess this gate automatically; a concept failure fails the whole run. Record the concept verdict in the build note.

**Boss theme test (mandatory at directing).** Ask: is the story's climax a confrontation with one dominant adversary or force the protagonist must overcome — a named antagonist, a champion or record-holder to beat, a monster storm, a rogue machine, an invading flagship, a final opponent? If yes, the story has a **boss theme**: write `Boss theme: <who/what, and the encounter rule>` in the brief, make one fact→mechanic row the boss encounter itself (suffix it `(signature)` when the boss is the story's core), and treat the boss-creator step in §3 as required, not optional. The finale of a boss-themed level is a crown encounter (see `skills/boss-creator/SKILL.md`), never a plain timing gate with extra hazards, and it must pass `node scripts/boss-review.mjs <id>` as well as the level critic. If the story has no dominant adversary (a rescue, a launch, a market move, a dance), write `Boss theme: none — <why>` so the skip is a decision, not an omission. Abstract boss themes from tragedies stay abstract (the storm system is the boss; victims are never combatants).

**Combat profile.** The default news level is a platformer (PHASER off) on one main height with shelves, chained to the next story (see §4). If the article itself is a fight — an invasion, a battle, a swarm assault, a chase-down, a tournament run — declare `Combat profile: contra` in the brief instead: the level is then built contra-style (PHASER on, stacked tiers with their spacing/graph rules from `skills/level-creator/SKILL.md`, the per-level gun rack, real boarder waves (actual `type: 'boarder'` homes in the level data, at least one per trigger — a trigger with no homes spawns nothing), and CROWN_SHIELD/boss finales where the story earns them). A contra brief also writes the level's **Height & Path Map** (tier names and height bands, how the player climbs/drops between them, what fights at each height, where the low and high paths split and rejoin) and maps at least one fact→mechanic row to a height or path choice — a battle briefed onto one flat deck wastes its profile. Fire aims Contra-style (forward, up, diagonal-up, down from the air; fan weapons fan perpendicular to the aim), so cross-height fights are designed with aimed fire plus tier placement, jumps, drops, and drones. Contra builds hold the contra difficulty band in `skills/level-creator/SKILL.md` (≥2.2 hazards/1k px, ≥5 types, tiered acts, pressured arena) — Level 24 shipped under it and played too easy. A boss-themed story almost always declares the contra profile, because a boss the player can only dodge is a gate wearing a costume; when a boss theme ships without the phaser, the brief must say how the player fights it (bonk rule, arena hazard the boss arms) and the boss panel judges that answer. Never brief shield-wave/clear mechanics without the phaser to clear them.

Before designing, list the story's **element inventory**: the concrete nouns a player should recognize on screen (for an AI-market crash: dollar signs, GPU cards, server racks, plunging chart lines, margin-call bells), on one `Element inventory:` line, with the `Signature elements:` line as a subset of it. Cap the inventory at **four** items: the gate needs three shown, and every extra item is another way to draw a missing-elements flaw (batch 19-21 listed 6-7 and failed on the surplus). Every item gets an **owner** named in the brief — `prop texture`, `themed hazard`, `set-piece geometry`, or `plate + beat` — and plate regions alone do not count as shown (tile framing crops them; the Phobos dishes were in the plate and judged missing at 0.08). An item with no owner is cut from the inventory now, not discovered missing at the critic. The finished level must show at least **three** of them as art, props, or hazards — a palette swap is not theming. Also name the **themed enemy** here: every news level gets at least one enemy actor whose look and behavior come from the story (panic-selling bot, flood debris drone, rescue-digger), never only reskinned generic hazards. If no existing hazard can carry it, the enemy steps below are mandatory, not skippable.
**Classify every signature claim** in the brief — `mandatory`, `optional`, or `visual metaphor` — and add a **Signature proof** block (observable + bypass test, per the Signature Mechanic Canvas in `skills/level-creator/SKILL.md`). A ride, bounce, delivery, or rhythm crossing the level does not require is optional however the copy phrases it; the brief says so before the critic discovers it. Renaming a stock system (rescue cages as "samples") does not create the claimed mechanic unless its acquire → carry → deliver state machine ships with it.

## 3. Generate the art with Muse Image + the repo's skills (do not skip to code)

Read and follow each skill file, in this order, doing the work it describes. Art for this workflow is **generated images** (the `muse.image_generation` tool), style-anchored to the shipped game; canvas paint is the fallback only when image generation fails twice.

Style anchor for every prompt: screenshot or describe the nearest shipped level first, then prompt with its exact palette, flat side-view style, chunky readable silhouettes, small gameplay scale, and "Space Chicken universe: a chicken with a jetpack, golden crown, cosmic platformer". Never prompt for a photorealistic or off-style look.

1. `skills/level-art-creator/SKILL.md` — generate the place: one wide background plate, plus platform/prop concepts. Save finals under `assets/news-<slug>/` (copy them out of `generated_images/`), candidates under `art-candidates/<brief-id>/`.
2. `skills/enemy-art-creator/SKILL.md` — generate the themed enemy named in step 2, isolated on a flat solid background so it can be cut out (chroma-key it in code, or regenerate asking for a clean cutout look), with its animation handoff. This step is required: a news level with zero story-themed enemies fails the brief. Reuse an existing hazard's _behavior_ if it fits, but the actor's look must be the story's.
3. `skills/level-art-selector/SKILL.md` — choose a coherent set and record `art-selections/<level-id>/selection.json`, including the final image paths as `asset_path`s. Creativity scoring applies: a set that is a palette swap over a shipped place is rejected here, however coherent. Run the **Art critic** on the selected previews at gameplay size and record its verdict with the selection; art the critic cannot distinguish from a shipped level goes back to step 1, not into the build.
4. `skills/enemy-animation-creator/SKILL.md` then `skills/enemy-animation-integrator/SKILL.md` — generate pose frames of the same actor (identical silhouette, palette, canvas and pivot per frame) or tween specs, then wire them in as real Phaser textures/anims.
5. `skills/boss-creator/SKILL.md` — required when the brief declares a boss theme (see the boss theme test in §2); otherwise only when the story's climax earns a distinct final encounter. A boss-themed level that skips this step fails the brief, however strong its gate finale looks.

Generated files do not exist to the game until they are wired: register every final image in `config/runtime-assets.cjs` `rootFiles`, load it in the scene preload (`this.load.image(...)`), and confirm it renders at gameplay size before calling the art done. An image left in `generated_images/` is not game art.

**Generated-prop path.** When an inventory element needs its own prop texture (background plates get cropped by tile framing, so plate regions alone do not guarantee a shown verdict): generate the prop isolated on flat magenta, chroma-key it with `node scripts/key-enemy.mjs <in> <out>`, save the RGBA final under `assets/news-<slug>/`, register it in `config/runtime-assets.cjs` `rootFiles`, preload it in `SpaceChicken.js`, place it in the level's `content.props` (`{ x, y, key }` — no SpriteFactory registration needed, `placeProps` renders any preloaded key), and give it beat coverage: props earn their own `setpiece-<key>` critic beat when placed >350px from every other beat, or duplicate the prop near an existing beat (opener/hazard/finale) so it appears in that shot.

## 4. Build the level with the level skill

Read and follow `skills/level-creator/SKILL.md` and its reference `skills/level-creator/references/spacechicken.md`. It owns the real deliverables: a `levels/<slug>.js` module registered in `levels/index.js`, its music registration, `config/runtime-assets.cjs` entries, and the story's title-screen wiring (`NEWS_PLATES` plus texture preloads in `SpaceChicken.js`; `NEWS_PLATE_KEYS`, `STAGE_ENEMY_KEYS`, and `ACTION_SENTENCES` in `Overlays.js`) — without those the story shows no title art. Apply the director table from step 2 as the level's gravity, hazards, objective, and topology — that table is the design input, the skill is the builder. Do not hand-roll a parallel level format, do not execute model-written code outside these files, and do not add any news UI beyond the title-screen section (set `content.news`, including the verified article `url`, and the section picks the level up).

Layout must not be a row of identical flat decks. Require: at least **three platform shapes/reads** (e.g. wide deck, narrow perch, stair run, angled/sloped-look set piece, vertical shaft or bridge), varied deck widths and heights, the story's signature set piece from the element inventory built as solid geometry, and the themed enemy placed where the player must deal with it (not decoration at the edge). Flat-and-same is a failed build: revise before playtesting. A `Combat profile: contra` build additionally requires the tiered layout from `skills/level-creator/SKILL.md`: at least two full tiers (three standable heights in at least one act), action at every height (same-tier gunfights, a fan lane, a drop-in, a defended high tier, a cross-height mover, or a vertical set piece), and one split where a low and a high path carry different costs and payoffs before rejoining — played branch by branch before the critic. Never copy a shipped level's deck x-list as a starting structure (the critic's `skeleton-rhyme` flag compares x sequences, not paints): choose the world width from the story's shape — a tower is short, a gauntlet is dense, a traverse earns length — and in a multi-level batch no two levels share width, deck count, and gravity band. Finale pressure must be visible in a frozen still (body hazard on the crown deck, horizontal or mostly-on beam, or staggered beam pair); see the finale contract in `skills/level-creator/SKILL.md`.

News levels form their own story chain outside the campaign: each story's `NEXT_LEVEL` points at the next news id in `NEWS_LEVEL_IDS` order, and the last story's `NEXT_LEVEL` is null (its crown ends the run on the finish screen). A new story appends to the chain: set the previous last story's `NEXT_LEVEL` to the new id and the new level's `NEXT_LEVEL` to null. News levels are PHASER-off with a token boarder wave — unless the brief declares `Combat profile: contra` (boss themes usually do), in which case build contra-style with the PHASER on and real waves. **Weapons need enemies:** PHASER bolts only damage boarders and bosses, so a contra news level places at least one `type: 'boarder'` home per `boarderWaves` trigger over the route, each over a deck at or past its release line — wave triggers with no homes are a failed build (the Level 24 defect: three triggers, PHASER, and pods with zero boarders). A shootable boss alone does not cover the route before the arena. PHASER-off news levels keep the token trigger with no boarder homes and no pods, because boarders without a gun are unkillable. Either way, do not brief shield-wave/clear mechanics (CROWN_SHIELD, adjudicator clears) unless the PHASER is on to clear them.

**Brief reconciliation (build-time, mandatory).** After authoring the level, diff every player-facing promise against the level data: each fact→mechanic row's mechanic must name a hazard type, gravity, objective, or topology value that actually exists in `levels/<slug>.js`, and the same audit covers the Signature Mechanic Canvas, the Novelty Ledger, the Topology Fingerprint, and the in-game instructions — staggered beams that shipped as one, a moving droneship that is static geometry, a plunge whose decks rise all get reconciled wherever they are written, not just in the table. For any promise that was cut or never built, either restore it in the level or amend every surface that states it and re-run `npm run critic:concept -- --brief docs/level-builds/<id>.md` to keep CONCEPT PASS. A brief that promises cut mechanics fails fidelity no iterate loop can fix — reconcile before playtesting.

## 5. Prove it plays, pass the critic, then report

1. Run `npm test` and fix what the new level breaks (reachability and polish tests are the contract — fix the level, not the test).
2. Play it for real: `node server.cjs`, open `http://127.0.0.1:3000/?level=<new id>`, and play from spawn to the crown (or drive it with the repo's bot scripts). A debug skip is not a playthrough. Boss-themed levels also run `node scripts/boss-review.mjs <id>` and need its PASS before the level critic counts as the final gate.
3. **Run the critic — the level is not done without a pass:**
    ```bash
    NEWS_BRIEF=docs/level-builds/<level-id>.md npm run critic:level -- <id>
    ```
    The run captures pilot telemetry and a screenshot beat sheet, **sends the screenshots to the critic panel as image evidence**, and scores both quality (fun/fairness/readability/novelty/pacing/theme) and **news fidelity**: each element-inventory item is judged visible/faint/missing from the shots, each fact→mechanic row is judged supported/contradicted/unsupported, and mechanic + visual fidelity must both clear the gate (see `skills/game-critic/SKILL.md`). A signature element that is missing, or faint/low-confidence and unconfirmed, fails the fidelity gate, and any unconfirmed `needs-human` blocks ship. The fidelity panel also judges the Space Chicken universe — jetpack chicken, crown goal, and readable hazard language visible in the shots — and a universe failure/flaw blocks like a missing signature element. On iterate, fix only the top contracted fix (see the report's `## Fix contract`) and re-run the full critic; on rework, return to step 2's artefacts. Maximum three loops. Without a TypeSafe key the run is mechanical-only: report `critic: mechanical-only` and never claim fidelity was judged.
4. Report in the terminal: the story (headline, outlet, time, URL), the fact→mechanic table, the files the skills produced, the play result, the critic report link (`docs/level-reviews/level-<id>.md`) with its quality and fidelity verdicts, and the URL to replay it. The report must name which three story elements the _critic_ marked shown (with their screenshot files, signatures flagged), the universe-check verdict, and which enemy is the themed one. If a step failed (wire down, skill missing, test red, panel unavailable), say which and what fallback was used — never claim a step ran when it didn't.

## Guardrails

- The repo stays the game; this skill only adds levels through the existing pipeline. No deployment unless the user asks.
- Same story in the morning briefing should be reproducible: record the story URL and the mechanic table in the level-build note the level-creator skill requires (`docs/level-builds/<level-id>.md`).
- Preserve unrelated working-tree changes. Do not publish, open-source, or post about this concept without the user's approval.
